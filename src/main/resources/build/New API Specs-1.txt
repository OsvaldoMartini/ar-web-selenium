I would like to propose building a large reusable library of automated test cases for our tool, generated with ChatGPT using our Avaloq CAPI APIs.

The objective is to preload the platform with approximately 1000 ready-to-use test cases organized in a clear business-oriented structure, so that both technical users and business users can easily navigate, understand, and reuse them.

The key principle is that the tool must speak the language of business, not APIs.
When a user creates or reads a test case, they should see a logical business flow, while the API layer remains an implementation detail described in plain language.

This will allow the platform to ship with a complete reference test library, making the tool immediately useful for demo, training, and production test design.

Import Format for the Tool

The tool should support importing test cases from structured files instead of hardcoding data.

Example format (JSON):

{

  "category": "Payments",

  "subcategory": "Internal Transfers",

  "testName": "Transfer between two retail accounts",

  "businessDescription": "Verify that a customer can transfer funds between two internal accounts and that balances are updated correctly.",

  "tags": ["retail", "transfer", "balance"],

  "parameters": {

    "sourceAccount": "${ACCOUNT_SOURCE}",

    "destinationAccount": "${ACCOUNT_DEST}",

    "amount": "${TRANSFER_AMOUNT}",

    "currency": "EUR"

  },

  "steps": [

    {

      "step": 1,

      "name": "Retrieve source account balance",

      "businessDescription": "The system verifies the available balance of the customer's account before executing the transfer."

    },

    {

      "step": 2,

      "name": "Execute transfer",

      "businessDescription": "Funds are transferred between the two accounts using the internal transfer service."

    },

    {

      "step": 3,

      "name": "Validate balances",

      "businessDescription": "The system confirms that the debit and credit were applied correctly."

    }

  ],

  "expectedResult": "The transfer is executed successfully and both account balances are updated.",

  "documentation": "This test validates the internal transfer process for retail banking customers."

}

Important:

No hardcoded values
All values must be parameterized
Parameters can be injected by the environment or test runner
Example parameters file:

{

  "ACCOUNT_SOURCE": "ACC_10001",

  "ACCOUNT_DEST": "ACC_10002",

  "TRANSFER_AMOUNT": "500"

}
