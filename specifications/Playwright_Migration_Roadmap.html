The core decision
The BancaStato failures — and the broader pattern of banking sites failing element detection — trace to Selenium's fundamental architecture: an external driver process communicating over the WebDriver protocol cannot reliably observe or control pages built on Shadow DOM, dynamic iframes, content-security-policy-restricted contexts, and modern Angular/React component wrappers. Playwright runs inside the browser process via CDP and a Chromium-patched protocol, giving it native access to all of these. The JS injection plugins (hoverPick, searchListAsync, actionExecutor) continue to operate over WebSocket — only the transport layer that launches and controls the browser changes.
Section 01 Why Migrate — Root Cause Analysis
Shadow DOM failures
  • Selenium XPath cannot cross shadow boundaries
  • BancaStato Angular components render inside closed shadow roots
  • Fallback to coordinates is brittle across screen resolutions
  • Playwright's locator() pierces open shadow roots natively; closed roots handled via CDP
Iframe / cross-frame problems
  • Selenium requires explicit switchTo().frame() — fragile when frame count changes dynamically
  • IframeInputLocator.java has 120 lines of workaround code
  • Playwright frameLocator() returns a scoped locator without switching context
  • All IframeInputLocator.java logic can be replaced with 3–5 lines
Click reliability
  • Selenium click() on Angular mat-* components routinely fails (overlay intercepts)
  • actionExecutor plugin exists specifically to work around this
  • Playwright auto-waits: scrolls into view, checks non-obscured, fires native events
  • The action executor plugin becomes a thin monitoring layer, not a primary click mechanism
Network & timing control
  • Selenium has no built-in network interception — page load timing hacks via executeScript("return document.readyState")
  • Race conditions on AJAX-heavy banking dashboards cause false "element not found"
  • Playwright: page.waitForLoadState(), page.waitForResponse(), page.waitForSelector() with auto-retry
  • Network interception available to stub slow endpoints during scanning
JS execution model
  • executeScript() takes positional Object... args — passed as arguments[n] in the script
  • executeAsyncScript() uses a callback convention — opaque and timing-dependent
  • Playwright page.evaluate(fn, arg): strongly typed, returns serialized JSON, supports async/await natively
  • Plugin wrapper adapts old IIFE scripts without editing plugin source
DevTools & diagnostics
  • Selenium logs require LoggingPreferences setup per driver — brittle across versions
  • PageDiagnosticDumper.java uses 80 lines of executeScript() for DOM introspection
  • Playwright exposes CDP directly: page.context().newCDPSession(page)
  • Console, network, and coverage events available as Java event listeners

Section 04 JavaScript Injection Strategy
ⓘ
Key insight: Your plugins (hoverPick, searchListAsync, actionExecutor) communicate results back through WebSocket — they do not rely on the return value of executeScript(). This means the injection call just needs to run the script; the data channel stays the same. You are not changing the plugin code — only the Java call that injects it.
⚠
Do not delete the Selenium injection calls. Comment them out in place with a // SELENIUM_FALLBACK: prefix. This keeps the fallback path for sites where Playwright inject fails and lets you re-enable without git archaeology.

The wrapper pattern — no plugin changes needed

Playwright's page.evaluate(fn, arg) takes one serialized argument. The plugins are IIFEs that receive positional arguments via arguments[n]. Bridge them with a one-line outer wrapper:

// ─── PerformCloneLoad.java:117 ───────────────────────────────────────────────

// SELENIUM_FALLBACK: ((JavascriptExecutor) driver).executeScript(
//     getJsHoverPick(), wsPort, sessionId, operationId, destination,
//     debugMode, timeout, langCode, mode, extraParam);

// NEW — Playwright injection: wrap the IIFE so arguments[] still works
String pluginScript = getJsHoverPick();          // unchanged plugin source
String wrapper = """
    (args) => (function(a0,a1,a2,a3,a4,a5,a6,a7,a8) {
        %s
    })(args[0],args[1],args[2],args[3],args[4],args[5],args[6],args[7],args[8])
    """.formatted(pluginScript);

List<Object> pluginArgs = List.of(
    wsPort, sessionId, operationId, destination,
    debugMode, timeout, langCode, mode, extraParam
);
page.evaluate(wrapper, pluginArgs);               // fire and forget — results come via WS

Async plugin (searchListAsync) — callback becomes Promise

The search plugin sends chunks via WebSocket — the executeAsyncScript callback return value is not actually used for the chunk data. Switch to a simple async evaluate; the WS chunks arrive as before:

// ─── PerformListElements.java:273 ────────────────────────────────────────────

// SELENIUM_FALLBACK: Object result = ((JavascriptExecutor) driver)
//     .executeAsyncScript(getJsSearchListAsync(), arg0,...,arg8, callback);

// NEW — fire async, results arrive via WebSocket chunks (no return value needed)
String asyncWrapper = """
    async (args) => {
        await new Promise((resolve) =>
            (function(a0,a1,a2,a3,a4,a5,a6,a7,a8,cb) {
                %s
            })(args[0],args[1],args[2],args[3],args[4],args[5],args[6],args[7],args[8], resolve)
        );
    }
    """.formatted(getJsSearchListAsync());

page.evaluate(asyncWrapper, List.of(arg0, arg1, arg2, arg3, arg4, arg5, arg6, arg7, arg8));
// Playwright page.evaluate() awaits Promises automatically

Init script — inject plugin on every page navigation

For plugins that must survive page navigations (actionExecutor), use addInitScript instead of per-call evaluate:

// ─── ARPlaywrightDriver.java (new) ───────────────────────────────────────────

// Inject once on BrowserContext; survives page.navigate() calls
String initWrapper = """
    (() => {
        window.__AR_WS_PORT__   = %d;
        window.__AR_SESSION__   = '%s';
        window.__AR_OP_ID__     = '%s';
        %s   // plugin code — already connects to WS on load
    })();
    """.formatted(wsPort, sessionId, operationId, getJsActionExecutor());

context.addInitScript(initWrapper);   // BrowserContext level — all pages inherit

Individual JS calls — direct Playwright equivalents

// ─── PerformActions.java — scattered executeScript calls ─────────────────────

// SELENIUM_FALLBACK: executeScript("arguments[0].scrollIntoView(true)", element);
page.locator(xPath).scrollIntoViewIfNeeded();

// SELENIUM_FALLBACK: executeScript("arguments[0].click()", element);
page.locator(xPath).dispatchEvent("click");      // or .click(new ClickOptions().setForce(true))

// SELENIUM_FALLBACK: executeScript("return arguments[0].textContent", element);
String text = page.locator(xPath).textContent();

// SELENIUM_FALLBACK: executeScript("return document.readyState");
page.waitForLoadState(LoadState.DOMCONTENTLOADED);

// SELENIUM_FALLBACK: executeScript("return document.documentElement.outerHTML");
String html = page.content();

// Iframes — no switchTo() needed
// SELENIUM_FALLBACK: driver.switchTo().frame(iframeElement); ... driver.switchTo().defaultContent();
Locator iframeInput = page.frameLocator("iframe[id='loginFrame']").locator("input[name='user']");

Section 07 Risk Register
RiskDetail & MitigationSeverityPhase
JavaFX + Playwright threading
Playwright is not thread-safe — all calls must be on the same thread that created the Playwright instance. ARControlPanel runs driver calls from multiple JavaFX threads. Mitigation: wrap all Playwright operations in a newSingleThreadExecutor() in ARPlaywrightDriver.java.
High
Phase 1
Playwright browser download
On first run, playwright install chromium downloads ~130MB. Air-gapped deployments or locked corporate networks will fail. Mitigation: bundle the Playwright browser zip in the distribution or point PLAYWRIGHT_BROWSERS_PATH to a pre-installed location via configuration.properties.
High
Phase 1
CSP blocking WS plugin
Some banking sites use Content-Security-Policy: connect-src 'self' which blocks the plugin's WebSocket connection to localhost. Mitigation: use Playwright's page.route() to intercept and rewrite the CSP response header. Not possible with Selenium without a proxy.
High
Phase 5
IIFE args mismatch
If a plugin references arguments[n] inside a nested function (not the outer IIFE), the wrapper won't map correctly. Audit each plugin's argument access pattern before Phase 3; adjust the wrapper's positional destructuring accordingly.
Medium
Phase 3
Closed Shadow DOM
Banking sites occasionally use mode: "closed" shadow roots — Playwright locators can't pierce these. Mitigation: CDP session (DOM.querySelectorAll on the raw node tree) as a second-pass fallback. Add this before removing the JS injection fallback.
Medium
Phase 5
Network idle timeout
waitForLoadState(NETWORKIDLE) requires 500ms of no network requests — some banking sites (chat widgets, analytics) never go idle. Mitigation: intercept and abort known noise URLs via page.route(), or use DOMCONTENTLOADED plus targeted locator.waitFor().
Medium
Phase 5
Engine jar compatibility
The Engine reads ElementDTO from JSON on disk. As long as no DTO fields change, Engine replay is unaffected. Risk: a developer accidentally adds a locator field to ElementDTO without updating the Engine. Treat any ElementDTO field addition as a cross-repo change requiring Engine update.
Low
Phase 4–6
JCEF co-existence
JCEF (embedded Chromium for the UI preview pane) and Playwright both bundle Chromium — two separate instances. This is intentional and fine, but confirm they don't conflict on DevTools port numbers. JCEF uses its own remote debugging port; Playwright uses a separate port allocated per BrowserContext.
Low
Phase 1
⚠
Critical — address in Phase 1: The Playwright threading constraint (single-thread model) and the browser download for offline deployments are blockers that must be resolved before any production use. Do not defer them to later phases.
